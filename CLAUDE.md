# CLAUDE.md — rules for every agent working in this repo

Read this file completely before doing anything. It overrides convenience. If a task seems to require breaking a rule here, stop and ask Marius.

## What this project is
Long-term computational research on Linear A / Minoan and related Bronze Age Aegean scripts. The goal is falsifiable, reproducible results fit for peer review, **not decipherment**. Negative results are results. Background: `docs/project-brief.md`, `docs/literature-survey-2026-10.md`. Working plan: `plans/phase2-analysis-plan.md` (task IDs A1–A7, hypothesis IDs H-A<n>-<nn>).

Marius works from secondary literature and does not read Linear B, Greek, Semitic or Anatolian languages. Explain philological notation when you use it.

## Methodological rules (non-negotiable)
1. **Null first.** No pattern counts until it beats an explicit null (shuffled corpus, random lexicon, permuted value grid…).
2. **Multiple comparisons.** Count every hypothesis tried, including failures. FDR-control exploratory batches.
3. **Pre-registration.** Write `hypotheses/H-*.md` and get it merged **before** running the test. Once merged, a hypothesis file is immutable (CI enforces this). Outcomes go in `hypotheses/outcomes/`.
4. **Validate on a known script first** (usually Linear B, via DAMOS or the NeuroDecipher data). If the method cannot recover the known answer at Linear A's scale, stop and record a negative result.
5. **LLM output is not evidence.** Any reading, sign value, segmentation or parallel that you (Claude) suggest is a hypothesis to test, never a fact. Say so when you suggest one.
6. **Confidence and sources.** Every claim carries a confidence level and a citation. Distinguish consensus / mainstream-but-contested / fringe.
7. **Negative results are recorded** with the same care as positive ones.
8. Decipherment-claim checklist: `docs/guardrails.md`. Apply it to your own proposals too.

## Data rules
- **Layers** (plan §0.1): L0 = sign IDs, numerals, fractions, damage flags (ground truth); L1 = conventional Linear B values; L2 = phonological hypothesis. Every result states its layer. A2/A3/A4/A7 compute on L0.
- **Never parse value-converted fields.** lineara.xyz's `translatedWords` / `transliteratedWords` already contain interpretations and fraction values (J shown as "½"). Parse sign codepoints only.
- **Raw data is not committed** unless its licence allows redistribution (see `DATA_SOURCES.md`). Commit the fetch script and `SHA256SUMS`; fetched files land in gitignored paths. A hash mismatch is a hard error, not a warning.
- `data/processed/` is generated by code. Never hand-edit it.
- **Held-out material** (KN Zg 57, KN Zg 58 — the Knossos sceptre; the frozen 20% split once created) must not be committed, fetched or read until the relevant predictions are tagged as frozen. Do not read the Kanta et al. 2025 *Ariadne* overview, *Anetaki II*, or the Kanta–Perna fractions paper. See `research-notes.md` 2026-11-02 for the existing blinding breach.
- **A web fetch is not blinded**: whoever runs it sees the whole page. Blinded checks are done by a separate agent returning only pre-specified fields, or by Marius.

## Workflow
- One branch and one PR per task ID: `a2.1-numeral-parser`, `a1.10-damos-check`. PR title starts with the task ID. Fill in the PR template.
- `main` is protected. Never push to it directly (the initial scaffold was the only exception).
- **Merging.** Agents open PRs under Marius's account, so GitHub cannot require an approval. The split below is a rule you must follow, not something GitHub enforces:
  - **Auto-merge allowed** (enable auto-merge on the PR; GitHub merges it when CI passes): code, tests, data fetchers, docs, plan checkboxes, research-notes entries.
  - **Marius merges by hand. Never enable auto-merge and never merge it yourself.** This applies to any PR that:
    - adds or changes anything under `hypotheses/`. Merging is the pre-registration commitment.
    - adds or changes anything under `findings/`. That is a claim.
    - changes the rules themselves: `CLAUDE.md`, `tools/check_guardrails.py`, `.github/`, `data/heldout.txt`.
  - For hand-merge PRs, write "**Needs Marius's merge**" and the reason as the first line of the PR description. For a finding, ask for a review by a separate Claude instance that did not produce it, and link that review.
  - If unsure which category a PR falls in, treat it as hand-merge.
- Results cite **corpus tag + commit hash** (e.g. `corpus-v1.0 @ abc1234`).
- A finding is `findings/NNN-<slug>.md`. Take the next free number at merge time; if two PRs collide, the later one renumbers.
- `research-notes.md` is **append-only**: add a dated entry at the end; never edit past entries (CI enforces this). Corrections are new entries referencing the old one.
- Update the task checkbox in `plans/phase2-analysis-plan.md` in the same PR that completes the task.
- Before finishing a session, leave the work resumable: what was done, what's next, what's uncertain — in the PR description or a research-notes entry.

## Code conventions
- Python ≥ 3.11, package `src/aegean/`, one subpackage per analysis (`corpus`, `arithmetic`, `affixes`, `signs`, `benchmark`, `typology`, `palaeography`).
- Exact arithmetic for numerals and fractions: `fractions.Fraction`, never floats.
- Every stochastic step takes an explicit seed, recorded in the output.
- Tests in `tests/`, run with `pytest`. Parsers get hand-checked fixture tests (document, expected parse, source used to check it).
- `notebooks/` is for exploration only; no result in a finding may depend on notebook state.
- Must run on one PC or free Colab. If something needs more, say so before building it.
