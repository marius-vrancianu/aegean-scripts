## Part 1 — Protocol

### Terms
- **Sign-group:** an item of kind `word` with two or more signs (fraction signs removed), neither edge marked broken, every sign identified; given as L1 values (`docs/layers.md`). Code: `aegean.benchmark.inputs.linear_a_groups`.
- **Eligible:** a sign-group the method can read (for M1: every sign has a consonant class or is a pure vowel). Hit rates are over distinct eligible sign-groups; the number not eligible is reported.
- **Hit rate** of an input under a lexicon: the share of its distinct eligible sign-groups for which the method returns at least one match.
- **Matched pseudo-lexicon:** a random lexicon that the method sees as the same size as the real one. It has exactly the real lexicon's number of distinct forms after the method's lexicon-side licences; each form takes the length of a real form drawn at random and letters drawn from the real lexicon's frequencies at that length and position. Code: `aegean.benchmark.nulls.matched_lexicon`.
- **False-positive rate:** the mean hit rate under the matched pseudo-lexicons. No language stands behind them, so each of their matches is false.
- **Excess:** real-lexicon hit rate minus the false-positive rate.

### Data
- **Linear A (primary input):** corpus-v1.0, default analysis set, **training split**, read through `aegean.corpus.load`. One reading per document: the first of SigLA, lineara.xyz, Younger that has the document (`resample.primary_reading`, the order used in the A1.11 baseline report).
- **Linear A (descriptive):** the same for each source separately. The sources are never merged.
- **Control:** Linear B words with an identified Greek counterpart, from the NeuroDecipher data (`linear_b-greek.cog` at commit `480bad24`, sha256 `0e8099cd…`; DATA_SOURCES.md), converted sign by sign to the same Unicode Linear B values; 918 distinct words of two or more signs. The control is a known negative for any lexicon that is not Greek or close to Greek. A lexicon that is needs a different control, named in its own file.
- The held-out split is not used and will not be. Finding 001 already ran M1 with this lexicon on the whole lineara.xyz word list, which included documents that are now held out, so the held-out split is not blind for this question.

### Tests
K = 1,000 matched pseudo-lexicons, drawn in sequence from `random.Random(20261114)`. The same 1,000 are used for Linear A and for the control.

- **Test 1 — real lexicon against noise, on Linear A.**
  p1 = (1 + number of pseudo-lexicons whose hit rate on the primary input is ≥ the real lexicon's) / (K + 1). One-sided.
- **Test 2 — Linear A against the Greek control.**
  1. Length bins: 2, 3, 4, and 5 or more signs.
  2. The control's hit rates (real lexicon and each pseudo-lexicon) are re-weighted to the primary input's distribution over those bins (direct standardisation; a bin the control lacks is dropped and the weights renormalised).
  3. D = (excess on Linear A) − (excess on the re-weighted control).
  4. The same D is computed for each pseudo-lexicon taken in turn as if it were the real one, its excess measured against the mean of the other K − 1.
  5. p2 = (1 + number of pseudo-lexicons whose D is ≥ the real lexicon's) / (K + 1). One-sided.

  Why a second test: a real lexicon can differ from pseudo-lexicons in ways that have nothing to do with Linear A (see "Known-script validation", point 3). Such a difference raises or lowers its hit rate on any input; D removes what Linear A and the control share.
- **p for the pair** = max(p1, p2). Both tests must pass, so no correction is needed between them.

Code: `tier1.HitTable.compare`, `tier1.difference_test`, `tier1.label`.

### Null model(s)
1. **Matched pseudo-lexicons** (above): the null of both tests.
2. **Greek control:** the null reference of Test 2.
3. Reported, deciding nothing:
   - **Finding 001 pseudo-lexicons** (same number of forms before expansion, overall letter frequencies; 1,000, seed 20261118). Known to be larger than the real lexicon as M1 sees it (about 743 forms against 664).
   - **Random sign strings** with the primary input's lengths and sign frequencies (20 repetitions, seed 20261116). This null compares sign-groups with noise, not lexicons.

### Decision rule (α = 0.05)
| Outcome | Condition | Meaning |
|---|---|---|
| **A — not supported** | p1 > α and p2 > α | The method cannot tell this lexicon from a lexicon of no language. Its matches carry no evidential weight. |
| **B — inconclusive** | exactly one of p1, p2 is ≤ α | Either the lexicon beats noise no more on Linear A than on Greek, or it differs from the Greek control without beating noise. Not evidence for a relationship. |
| **C — supported at Tier 1** | p1 ≤ α and p2 ≤ α, after the batch correction below | The method finds this lexicon in Linear A more than noise, and more than in Greek. This is not evidence of a relationship yet: it qualifies the pair for Tier 2 (power, unrelated-language lexicons). |

- **Multiple comparisons.** The Tier 1 batch is every (method, lexicon) pair ever run under this protocol, including failures. Benjamini–Hochberg at q = 0.05 is applied to the pair p-values of the whole batch each time a pair is added, and every outcome file lists the batch and the adjusted values. Outcome C needs an adjusted pair p ≤ 0.05. With one pair, the adjusted value equals the raw one. An earlier pair's label changes only if its adjusted p crosses 0.05; the outcome file of the pair that caused it says so.
- **Only the primary input decides.** Per-source rows, by-length rows and every other table are descriptive.
- **Stability is reported, not decided on.** The A1.14 harness gives intervals for the hit rate, the false-positive rate, the excess and D (1,000 draws, seed 20261115, p_doubt 0.5, strata = sites), and the share of combined draws in which each test is ≤ α.
- **Deviations.** If the code fails or a bug is found after results are seen, the fix and its effect are recorded in the outcome file and the run is repeated with the same seeds. Constants are not changed.

**Power check (required).**
- n: 414 distinct eligible sign-groups in the primary input (321 SigLA, 400 lineara.xyz, 195 Younger). Control: 902 of the 918 words are eligible for M1.
- Smallest attainable p, both tests: 1/1001 ≈ 0.000999, below α. Under Benjamini–Hochberg it stays attainable for a batch of up to 50 pairs (0.05/50 = 0.001). A batch beyond 50 pairs needs a new protocol with more pseudo-lexicons.
- Size of effect needed (approximate, not measured on Linear A): on the control the pseudo-lexicons' hit rates have a standard deviation of 0.013. If it is of that order on Linear A, Test 1 needs an excess of roughly 0.03, about a dozen of the 414 sign-groups, and Test 2 somewhat more. The outcome file reports the measured values.
- What Tier 1 cannot show: that the method would find a related language if there were one. That is Tier 2. An outcome A therefore says the method is uninformative for this lexicon; it says nothing about what language Linear A is.

### Reported besides the decision (descriptive)
By length; per source; lexicon-size sensitivity (Finding 001 pseudo-lexicons of 0.5, 1, 2 and 4 times the real size, 20 each, seed 20261117); readings per sign-group and the share of the reading space the lexicon covers; the method's licences under the six headings of `docs/guardrails.md`, item 3.

## Part 2 — First run: M1 × Hebrew verbs

## Hypothesis
With the Hebrew verb lexicon, M1 matches Linear A sign-groups more often than it does with matched pseudo-lexicons (Test 1), and by a wider margin than on Linear B words of known Greek meaning (Test 2).

This is the claim a root-matching decipherment needs. **Prediction, stated in advance: outcome A.**

## Data
As in Part 1.
- **Method:** M1 with the default `M1Rules`: the licences of di Mino 2026 as encoded for Finding 001. `tests/test_benchmark_m1.py` checks the port against the original script.
- **Lexicon:** `hebrew-strong-verbs`: verb lemmas (Hebrew and Biblical Aramaic) of Strong's dictionary, openscriptures HebrewLexicon at commit `21c9add1`, sha256 `a628f4f8…`, CC BY 4.0; 502 consonant-class skeletons, 664 forms after M1's interchanges.

## Test
Part 1, without change.

## Null model(s)
Part 1, without change.

## Known-script validation
Done before registration; none of it used Linear A sign-groups.
1. **The method is the one Finding 001 tested.** On 20,775 sign strings the port and the original script return the same parse, and with the Finding 001 inputs the port reproduces every figure of its table (research-notes 2026-11-14).
2. **The benchmark recovers a known answer on synthetic corpora** (`tests/test_benchmark_tier1.py`): a lexicon built to fit the sign-groups gives outcome C; a matched pseudo-lexicon used as if real gives A; a lexicon that fits the control equally gives B; a lexicon that is merely larger than the null passes Test 1 and fails Test 2.
3. **Calibration of the matched null on Linear B** (control only, 902 words, the 1,000 pseudo-lexicons of this protocol): real Hebrew 0.532, pseudo-lexicons 0.512 (95%: 0.486–0.538); excess +0.020; one-sided p = 0.064, lower-tail p = 0.944. The real lexicon is inside the null's range on Greek words, with a small positive shift. Under the Finding 001 null the same comparison gives −0.029 and puts the real lexicon in the lowest 2.5%.
   - Pass criterion, set after seeing these figures: the control is not outside the central 95% of the matched null. It passes. Because the shift is positive and not negligible, Test 1 alone could be passed by a lexicon unrelated to Linear A; that is why Test 2 is part of the decision.
4. **Not available at Tier 1: a known positive.** No test here shows that M1 would detect a Semitic language written in a Linear B-like syllabary. See the power check.

## Decision rule
Part 1, without change. Batch size 1.
